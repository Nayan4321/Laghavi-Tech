1Install and activate

Each Rinnovo Pro needs WooCommerce and the free Rinnovo Subscriptions & Licenses plugin. Your download from My Account is a package with two zips: the Pro plugin and the Rinnovo Box Builder (shared by all Rinnovo Pros).

  1. In WordPress go to Plugins › Add New, search "Rinnovo Subscriptions & Licenses", click Install now, then Activate.
  2. On your computer, unzip the package you downloaded. You get two zips.
  3. Plugins › Add New › Upload Plugin: upload the rinnovo-media-archives-pro zip and activate it. Do the same with rinnovo-box-builder.zip.
  4. Go to WooCommerce › Media Archives Pro license. Paste your license key from My Account › Licenses on laghavi.site and click Activate. Status turns Active and "Updates until" shows the end of your license year.
  5. Updates now arrive in Dashboard › Updates like any other plugin.

Already using another Rinnovo Pro? Skip step 1, and upload the Box Builder zip only if it is not installed yet.

3First setup

  1. Media Archives › Overview & analytics: pick what you are building (A video library, B podcast network, C stock media, D private portals). Only the settings you need are shown.
  2. Create the subscription products (for example Basic Monthly, Pro Yearly).
  3. WooCommerce › Media Archives › 1 · Plans & Quotas: for each plan choose its Products and write its Features and quotas. Save.
  4. 2 · Media Providers: enter the keys of the service your media is on (Bunny, Cloudflare Stream or S3 / CloudFront). Save.
  5. Media Archives › Add media item: choose Type, Hosted on, Who can play it. Publish.
  6. Create a page with [media_library] (the wizard offers to). Buy a plan as a test customer and play an item.

5Media providers

  1. Bunny Stream: library ID, API key and token key; turn on token authentication in Bunny.
  2. Cloudflare Stream: account ID, API token and signing key; require signed URLs on each video.
  3. S3 + CloudFront: bucket private, a CloudFront key pair; the plugin signs short-lived links.

Keys stay on your server and are never sent to the browser.

6Private podcast feeds

Every subscriber gets their own feed address in their media account, which works in any podcast app. If a feed is shared, it is flagged (many devices or places); rotate it with one click and the old address stops working. Storage addresses are never in the feed.

7How each play is protected

  1. Who is asking: logged in and subscription valid.
  2. What their plan allows: the item, the quota, device and stream limits.
  3. A short-lived signed link or provider token is created.
  4. The play or download is recorded; unusual activity raises an alert (geo alerts are warnings, they never block travellers automatically).

Signed links stop sharing of links and downloads of your storage, but they are not DRM: a determined viewer can record the screen. DRM streaming is a future integration.
